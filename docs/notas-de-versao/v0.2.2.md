toolkit v0.2.2

Correção: a interface de terminal (TUI) não abria no Windows. Agora abre, e o comando de uma linha já a abre ao terminar de instalar.

## O que mudou desde a v0.2.1
- **A TUI abre no Windows.** O toolkit exigia a variável `TERM`, que o cmd, o PowerShell e o Windows Terminal não definem, e caía na ajuda sem avisar. No Windows basta um console interativo.
- **`toolkit tui`:** abre a interface de forma explícita e, se não puder, diz por quê (por exemplo, no Git Bash/mintty use `winpty toolkit.exe tui`).
- **O instalador abre a TUI ao terminar.** `irm .../win.ps1 | iex` (Windows) e `curl ... | sh` (Linux e macOS) abrem `toolkit tui` na própria janela depois de instalar ou atualizar, só com terminal de verdade. Nunca abre em CI, em sessão remota nem com entrada ou saída redirecionada. Para não abrir: `TOOLKIT_NO_LAUNCH=1` (ou `-NoLaunch` no `win.ps1` salvo, `--no-launch` no `unix.sh`). Se a TUI não abrir, a instalação continua valendo e o script diz como abrir depois.
- **Em CI o `toolkit` sem argumentos nunca abre a TUI sozinho** (mostra a ajuda).

## Atualizar
`toolkit update` (a partir da v0.2.1). Ou rode o instalador de novo:

Windows (PowerShell):
```
irm https://github.com/PiluTech/toolkit/releases/latest/download/win.ps1 | iex
```
Linux e macOS:
```
curl -fsSL https://github.com/PiluTech/toolkit/releases/latest/download/unix.sh | sh
```

## Arquivos
`toolkit_<so>_<arch>` (binário cru; `.exe` no Windows), `checksums.txt`, `unix.sh` e `win.ps1`. Os binários de macOS são assinados (Developer ID) e notarizados pela Apple.

## Limites conhecidos
- `toolkit --version` ainda não existe; use `toolkit version`.
- O lançamento automático da TUI com console real do Windows ainda não tem teste automático; o smoke manual no Windows, no macOS e no Linux continua por fazer. Relate o que encontrar.
- O CI do Windows ainda é experimental (falha só no teste de permissões do release).

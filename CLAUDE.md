# toolkit — índice

Ferramenta em Go para preparar máquinas Windows, Linux e macOS com um comando (catálogo YAML de apps, providers, receitas multi-etapa que sobrevivem a reboot, TUI Bubble Tea, bootstraps). Nome provisório, centralizado em `internal/buildinfo`.

**Estado atual:** repositório `PiluVitu/toolkit`, **privado por enquanto** (planejado para ser público). Licença MIT. As 22 perguntas da proposta foram respondidas, com todas as recomendações aceitas (`docs/decisoes.md`). **Fase 1 (esqueleto) em andamento** desde 2026-11-11, em PRs pequenos: PR1 módulo + Cobra `version` + gate local (feito), PR2 `exec` (feito), PR3 `platform` (feito), PR4 `catalog` (feito), PR5 `toolkit list` (feito). **Fase 1 completa e aprovada.** **Fase 2 (providers + `toolkit install`) liberada em 2026-11-11**, em PRs empilhados: PR1 Crivo Cf/Zl/Zp (feito, #8), PR2 núcleo `providers` (feito, #9), PR3 winget (feito, #10), PR4 brew (feito, #11), PR5 apt (feito, #12), PR6 dnf+pacman (feito), depois apt, dnf+pacman, flatpak e `install`/`--dry-run`.

## Código (fase 1)
- `cmd/toolkit/main.go`: só chama `cli.Execute`. `internal/cli`: comandos Cobra (hoje só `version`). `internal/buildinfo`: nome, versão, commit e data (via `-ldflags -X`). `internal/msg`: strings de UI em pt-BR.
- `internal/exec`: `Runner` (Run/LookPath), `OSRunner` (exit code != 0 não é erro; `Timeout` vira `ErrTimeout` só se o ctx derivado expirou, prazo do chamador sai como erro do ctx; timeout/cancel encerram o grupo de processos (Unix, `Setpgid` + SIGTERM/SIGKILL em `-pgid`) ou o Job Object (Windows); `Elevate` = `sudo -n -- [env VAR=..] cmd` no Unix (nunca pede senha, recusa do sudo = `ErrNotElevated`) e `ErrNotElevated` no Windows sem token; teto de memória `MaxOutput` por stream, `Result.Truncated`; falha do tee é reportada ao fim), `DryRunRunner` (FALHA FECHADO: só executa `Cmd.ReadOnly` sem `Elevate`; o resto só é registrado em `Plan()`/`Planned()`; `CheckElevation` põe `ErrNotElevated` no plano). `Cmd.Env` só aceita `NOME=valor` (`validateEnv`, `ErrInvalidEnv`, no `OSRunner` e no `DryRunRunner`; com `Elevate` o Env vira argumento do `sudo -n -- env`). Todo `Cmd` de leitura precisa de `ReadOnly: true`. `internal/exec/exectest.FakeRunner`: respostas por linha de comando (`On`, `OnElevated` para `Elevate`, `WithPath`, `Exit`), comando sem roteiro falha o teste. Testes do `OSRunner` só re-executam o binário de teste (helper process) e um `sudo` falso num PATH temporário, nunca comando do sistema.
- `toolkit list` (`internal/cli/list.go`): tabela ou `--json` dos apps do catálogo com os gerenciadores do SO (`--os`, padrão o atual; fallback `any`), `--category`, `--catalog <arquivo>` (mescla sobre o embutido), `--catalog-replace`; ids do embutido substituídos pelo catálogo local são avisados em stderr (o `--json` fica limpo); a tabela escapa tudo que não é imprimível (`printable`, segunda camada depois da carga). `--catalog` por URL e `--catalog-sha256` existem como flags mas a URL é recusada com mensagem clara até haver o pacote `download`. A coluna "instalado" do README chega com os providers (fase 2). Dependências do CLI são injetadas via `Deps` (`NewRootCmdWith`).
- `internal/catalog`: `Parse(file, data)` valida sobre `yaml.Node` e relata TODOS os erros como `arquivo:linha:col: app "x": ...` (`Errors`); chave desconhecida, **chave repetida em qualquer nível**, âncora/alias/`<<`, categoria fora da lista fixa, campo de outro provider, brew com formula xor cask, `{{var}}` desconhecida e variável de versão sem lista em `versions` (inclusive em `args`) são erro; `args` só com textos validados por `tmpl.Validate`. `url` passa por `CheckURL` (https, host público com ponto, sem userinfo/fragmento/espaço/controle, sem template no host, sem IP literal nem localhost, porta só 443; revalidar depois da expansão) e exige `sha256` de 64 hex. **Caractere de controle ou de formatação** (`unsafeRune`: `unicode.IsControl` (< 0x20, 0x7f, C1; ESC, OSC, BEL, CR, quebra de linha, tab) mais Cf (bidi U+202E, zero width, BOM, ZWJ), Zl U+2028 e Zp U+2029) em QUALQUER texto do arquivo (chaves e valores) é erro, e a mensagem cita o `U+XXXX`, nunca o byte; cada item de `versions` tem de passar em `tmpl.ValidValue`. Limites: arquivo 1 MiB (`MaxFileSize`), 2000 apps (`MaxApps`). `Merge(base, ext, replace) (*Catalog, replaced []string)` (cópia profunda, nil seguro, devolve os ids substituídos para o chamador avisar), `LoadFile` (abre, exige arquivo regular, lê com `LimitReader`; só caminho local; URL com `--catalog-sha256` fica para o pacote `download`), `App.InstallersFor(goos)` com fallback `any`, `App.VersionVars(pedida)` (versão tem de estar em `Versions.List`). Templates ficam intactos na carga; `internal/tmpl` resolve (`Names`/`Validate`/`Expand`, sem `text/template`; valor só `^[A-Za-z0-9][A-Za-z0-9._+~-]*$`, ou seja, nunca começa com `-`, e sem `..`). Catálogo padrão em `catalog/catalog.yaml`, embutido por `assets.go` (`toolkit.CatalogYAML`); `assets_test.go` confere as 7 entradas e que toda `url` tem sha256. Dependência nova: `go.yaml.in/yaml/v3` v3.0.4 (decisão 4).
- `internal/platform`: `SystemDetector.Detect` (OS, arch normalizada, distro via `ParseOSRelease` (ID/ID_LIKE em minúsculas, ID fora do padrão vira vazio), versão, boot ID, usuário real, gerenciadores no PATH). SO fora de windows/linux/darwin = `ErrUnsupportedOS`. Usuário real: `SUDO_USER` só com euid 0, nome em formato Unix válido, usuário existente (`os/user.Lookup`) e `SUDO_UID` igual ao uid dele; senão o dono do processo (`os/user.Current`); `USER`/`USERNAME` nunca são lidos. Leituras só pelo `exec.Runner` (sempre `ReadOnly: true`, por caminho absoluto: `/usr/bin/sw_vers`, `/usr/sbin/sysctl`, `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`) ou funções injetadas; falha de leitura opcional deixa o campo vazio. `IsAdmin` no Windows vem de `IsElevated` injetado (a implementação real, com `x/sys/windows`, chega no pacote `elevate`). `ResolvePaths(Info, Env) (Paths, error)`: Windows admin `C:\ProgramData\toolkit` FIXO (nunca a variável `%ProgramData%`), usuário `%LOCALAPPDATA%\toolkit` (só se absoluta, `X:\` ou UNC `\\servidor\...`; senão `<Home>\AppData\Local`); Linux root `/var/lib/toolkit`, usuário `$XDG_STATE_HOME/toolkit` (só absoluto; relativo é ignorado) ou `~/.local/state/toolkit`; macOS `/Library/Application Support/toolkit` (admin) ou o equivalente em `~/Library`. Usuário sem Home absoluto = `ErrNoHome`; SO desconhecido = `ErrUnsupportedOS`.
- `internal/providers`: contrato dos gerenciadores. `PackageRef` (instalador com templates resolvidos por `RefFrom`, que revalida a URL), `Provider` (`Name`, `Available` via `Runner.LookPath`, `Validate`, `IsInstalled`, `ListVersions`, `Install(version)`), `Preparer` opcional (brew update/apt-get update uma vez por execução, estado na instância; é mutação), `InstallResult` (`AlreadyInstalled`, `RebootRequired`, `Version`) e erros tipados (`ErrNotFound`, `ErrNoApplicableInstaller`, `ErrHashMismatch`, `ErrNeedsAdmin`, `ErrRetryable`, `ErrVersionUnsupported`, `ErrInvalidRef`). O catálogo NÃO restringe id/package/formula: cada provider valida com `CheckName` (letra/número na frente, nunca `-`, só `[A-Za-z0-9._+@/-]`, sem `..`, até 200) e `OnlyFields`; versão pedida ou devolvida pelo gerenciador passa por `ValidVersion` (aceita `:` da época Debian e `~`, por isso não usa `tmpl.ValidValue`). `Registry.Candidates` percorre os instaladores do SO (fallback `any`) e devolve os com provider registrado, `Available` e `Validate` ok (o resto vira `Skip` com motivo); `InstallApp` valida a versão UMA vez no começo (`CheckVersionArg`: vazia, `latest` ou `ValidVersion`, senão `ErrInvalidRef` antes de qualquer método do provider; o chamador ainda passa por `App.VersionVars` para ids com template), depois por candidato: IsInstalled (com versão, `SameVersion` ignora a época do Debian: `1:2.45-1` casa com `2.45`) → `SupportsVersion` (sem mutação, antes do Prepare, para não rodar apt-get/brew update à toa) → Prepare → Install; pula para o próximo em `ErrNoApplicableInstaller`, `ErrNotFound` e `ErrVersionUnsupported` (se todos recusam, o último erro é o resultado) e encerra nos demais. O contrato leitura/mutação é forçado pelo código: `providers.NewRunners(r)` dá `Read` (`exec.ReadOnlyRunner`: recusa `ReadOnly=false` ou `Elevate`, para `Available`/`IsInstalled`/`ListVersions`) e `Mutate` (`exec.MutatingRunner`: recusa `ReadOnly=true`, para `Install`/`Prepare`); Cmd no Runner errado volta `exec.ErrWrongRunner`. `@` e `/` no nome são sintaxe do gerenciador (`python@3.12`, `pkg/suite`, `tap/formula`) e escolhem versão/origem: responsabilidade do autor do catálogo. `PackageRef.VersionInID` (marcado por `RefFrom` quando um template de versão foi aplicado a id/package/formula/cask, ex.: `python@{{major_minor}}`): `InstallApp` NÃO passa a versão ao provider desse candidato (sem `--version` no winget, sem `=versão` no apt, sem `ErrVersionUnsupported` no brew); teste `versioned_test.go` cobre `python@3.12` nos três. `args` do catálogo só existem para `url`/`github-release` (fase 5): vão sempre DEPOIS do arquivo e nunca no lugar de opção; os providers de gerenciador recusam `args` (teste por provider).
- `internal/providers/winget`: `winget list --id X -e` (ReadOnly; 0x8A150014 = não instalado), `winget show --id X -e --versions` (ReadOnly), `winget install --id X -e --source winget --silent --accept-package-agreements --accept-source-agreements --disable-interactivity [--version V]` (NÃO ReadOnly, sem Elevate: o winget pede o UAC sozinho). Exit codes comparados como `uint32(res.ExitCode)` (positivo ou negativo) e traduzidos conforme a tabela de `arquitetura.md` 3.3 (nunca `--ignore-security-hash`, hash divergente não retenta; INSTALL_IN_PROGRESS tenta 3 vezes com backoff injetável). `ParseTable` acha as colunas pelas palavras do cabeçalho e a linha de traços, descarta spinner/`\r`; Id = coluna 2, Versão = coluna 3 (prefixo `<`/`>` removido). Fixtures em `testdata/` são SINTÉTICAS (README do diretório): trocar pelas saídas reais (en-US e pt-BR) no smoke da VM. usa `providers.NewRunners` (leitura e mutação em Runners separados). `providers.Snippet` limpa a saída do gerenciador antes de ir a mensagem de erro.
- `internal/providers/brew`: `brew list --versions --formula|--cask X` e `brew info --json=v2` (ReadOnly), `brew install --formula|--cask X` (mutação), `brew update` uma vez por execução em `Prepare` (`sync.Once`, erro memorizado). `IsInstalled`/`ListVersions` também chamam `Validate` (o brew não tem `--`); `IsInstalled` separa "não instalado" (`No such keg`, `is not installed`, stderr vazio) de falha do brew (erro). Cask de `.pkg` pode pedir a senha do sudo ao próprio brew: sem terminal isso falha e vira `ErrNeedsAdmin` (instale uma vez à mão). Todo Cmd leva `HOMEBREW_NO_AUTO_UPDATE=1` e `HOMEBREW_NO_ENV_HINTS=1`; NUNCA Elevate; como root (`Euid()==0`, injetável) todo método devolve `ErrRoot` sem executar nada. `SupportsVersion` sempre recusa (só a versão atual; outra versão = fórmula versionada no id, ex. `python@3.12`). `Validate`: exatamente um entre formula e cask, `CheckName`.
- `internal/providers/apt`: `dpkg-query -W -f='${db:Status-Status}\t${Version}\n' pkg` e `apt-cache madison pkg` (ReadOnly; só o nome, sem `/suite`), `apt-get update` (uma vez em `Prepare`, `sync.Once`) e `apt-get install -y pkg[=versão]` com `Elevate` e `DEBIAN_FRONTEND=noninteractive` (sob sudo vira `sudo -n -- env DEBIAN_FRONTEND=... apt-get ...`). Exit 100 = qualquer erro: `classify` lê o stderr (`Unable to locate package` → `ErrNotFound`, `Version ... was not found` → `ErrVersionUnsupported`, lock → `ErrRetryable`, permissão → `ErrNeedsAdmin`); `sudo -n` sem credencial (`exec.ErrNotElevated`) vira `ErrNeedsAdmin`. As versões do madison trazem época (`1:2.43.0-1ubuntu7`) e passam por `ValidVersion`. `providers.SameVersion` agora compara a época quando o PEDIDO traz (`3:2.45` ≠ `1:2.45-1`; ausente = 0). Fixtures sintéticas (README no `testdata`).
- `internal/providers/dnf`: `rpm -q --qf %{EVR}\n pkg` e `dnf list --showduplicates pkg` (ReadOnly; `ParseList` cobre dnf4 (nome longo quebrado em duas linhas) e dnf5, só o nome exato), `dnf install -y pkg[-versão]` com `Elevate`, sem Prepare (o dnf atualiza metadados sozinho). `Validate` recusa `/`, `@` e `.rpm` (o dnf lê `dir/x.rpm` como arquivo local e `@grupo` como grupo). Erros pelo stderr (`No match for argument`/`Unable to find a match` → `ErrNotFound`, ou `ErrVersionUnsupported` se havia versão fixada). Fixtures sintéticas.
- `internal/providers/pacman`: `pacman -Q pkg` e `pacman -Si pkg` (ReadOnly; `-Q` sem o `repo/`), `pacman -S --needed --noconfirm pkg` com `Elevate`, NUNCA `-Sy` (atualização parcial). `SupportsVersion` sempre recusa (`ErrVersionUnsupported`). `apt.Validate` agora recusa nome terminado em `.deb` (o apt-get o lê como arquivo local).
- Toolchain: Go 1.27.3 (o `go.mod` baixa sozinho via `GOTOOLCHAIN`) e golangci-lint v2.15.0 em `~/.local/bin`, instalado por `scripts/instalar-ferramentas.sh` (baixa o tarball oficial e confere o SHA-256 versionado em `tools.sha256`; o workflow usa o mesmo script; `--verificar` confere que todo hash do `tools.sha256` é da `VERSION` do script, e `scripts/instalar-ferramentas_test.sh` testa isso no gate). Config em `.golangci.yml` (sem `misspell`: ele é só inglês e acusa pt-BR).
- Gate: `scripts/ci.sh` (ou `make ci`; `~/.local/bin` entra no FIM do PATH; o gofmt vai por `scripts/check-gofmt.sh`, que reprova também sintaxe quebrada, com autoteste em `scripts/check-gofmt_test.sh`). Actions do workflow fixadas por SHA de commit (versão em comentário) e checkout com `persist-credentials: false`. Heavy pelo build-slot: `~/.maestri-local/build-slot.sh ./scripts/ci.sh`. `.github/workflows/ci.yml` só em `workflow_dispatch`.

## Regras do projeto
- Escrever como repositório público, mesmo enquanto ele está privado: nada de dado de cliente, segredo, IP, e-mail ou referência a projetos privados em código, docs, testes ou mensagens de commit.
- Trabalhar por fases do briefing e parar ao fim de cada uma para revisão.
- Nunca executar instaladores, winget, dism, apt ou reboot de verdade na máquina de desenvolvimento: usar o `exec.Runner` mockado (`internal/exec/exectest`) ou `--dry-run`.
- Nada de download sem SHA-256 e nenhum `curl | bash` de terceiros. Nada que contorne licenciamento.
- Dependências com versão exata no `go.mod` e `go.sum` commitado. Fora da lista do briefing, só com justificativa.
- Antes de entregar: `scripts/ci.sh` (gofmt, go vet nos 3 GOOS, golangci-lint, go test, cross-compile dos 6 alvos com CGO_ENABLED=0). O gate é local; os workflows do GitHub Actions ficam em `workflow_dispatch` até a fase 1 estabilizar.
- Manter este índice atualizado quando surgir doc novo em `docs/` ou mudar um fluxo.
